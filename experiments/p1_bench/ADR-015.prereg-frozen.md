## 1. Question

Can QuBLAR's annealer take a general integer-weighted Ising/MaxCut instance (per-edge weights,
including +-1 and fully connected), keep its energy exact, reproduce every committed Gset number
bit for bit, and report time-to-solution the way the Ising-machine literature does?

This is an instrument ADR. It makes no claim to beat any solver. Performance work is P2/P3.

## 2. What is built (declared before any code)

1. **Format, integer path.** A weighted sparse graph: `n`, edge list (u, v, w) with `w` an exact
   signed integer (int32 storage, int64 accumulation), and a symmetric CSR (int64 row offsets,
   int32 column, int32 weight). Loader for the rudy/Gset text format: header `n m`, then m lines
   `u v [w]`, 1-indexed, missing w = +1. Refused (exit 2, message): a non-integer weight (that is
   the float path, which stays `BinaryProblem`, untouched), a self-loop, a duplicate edge, an index
   out of range, or an edge count different from the header.
2. **Energy convention.** x in {0,1}^n. cut(x) = sum over edges of w_uv [x_u != x_v], with the
   file's weights as given (this is the convention of Gset and of K2000's published best cut 33337).
   Energy E(x) = -cut(x), the same convention as `tools/gset_bench.cu` (lambda = -1).
3. **Engine, integer path.** Single-spin Metropolis with the exact schedule and RNG stream of
   `argos::anneal_branch` (ising_recon.hpp): start from x = 0; sweep variables in index order;
   temperature `t_hot * (t_cold/t_hot)^frac`, `frac = min(1, sweep / max(1, anneal-1))`, then
   `t_cold` for the hold sweeps; state `seed * 0x2545F4914F6CDD1D + 1`, splitmix64, a uniform drawn
   ONLY when dE > 0; accept `dE <= 0 || u < exp(-dE / T)` with dE converted to double. dE is
   computed exactly in int64 from a maintained local field f_i = sum_j w_ij s_j (s = 2x - 1):
   dE_i = -s_i f_i. On a flip, f_j -= 2 w_ij s_i(old) for every neighbour. The energy is tracked
   incrementally in int64. For weight +1 graphs this makes the same accept decisions as
   `anneal_branch` with lambda = -1, so the assignments must be identical (rule R1).
   `src/ising_recon.hpp` and `BinaryProblem` are not modified.
4. **Harness.** `tools/gset_bench.cu` keeps its legacy mode unchanged (`gset_bench <graph>` =
   frozen schedule, seeds 1..8, same output bytes, same `anneal_branch` code path). A new harness
   mode runs R independent runs (seeds 1..R) of the integer engine on a thread pool and writes a
   CSV with dot decimals, one row per run and one summary row per cell. `gset_bench` is added to
   `build.bat`; a fast self-check mode is added to `check.bat`.

## 4. Schedule and budgets (frozen)

- Temperatures: t_hot = 5, t_cold = 1e-3 (the frozen Gset/MAP schedule), for EVERY instance.
  Not scaled to K2000's local fields (|f| ~ sqrt(2000) ~ 45); that is prediction R7.
- Budgets: **B1** = 400 anneal + 20 hold sweeps (the frozen schedule), **B10** = 4000 + 200,
  **B100** = 40000 + 2000.
- Runs: R = 64 (seeds 1..64) at B1 and B10; R = 16 (seeds 1..16) at B100.
- Cells: 11 instances x 3 budgets = 33 cells.
- Threads: 16 worker threads (the machine has 32), one run per thread at a time.
- Cap: 30 minutes wall per cell. A run not started before the cap is not started; that cell
  then has fewer than R runs.

## 5. Measures and TTS definition

- Per run: cut (int64, recomputed from the edge list), E_tracked (int64, incremental), E_scratch
  (int64, recomputed over the CSR), consistent = (cut == -E_tracked == -E_scratch), wall time of
  the anneal alone (steady_clock around the run, excluding load), success = (cut >= target).
- Per cell: best cut, gap % = 100 (best - target) / target, mean cut, p = successes / R,
  t = mean per-run wall time (s).
- **TTS99** = t * ln(0.01) / ln(1 - p) for 0 < p < 0.99; = t for p >= 0.99; = inf for p = 0.
- **95% CI**: bootstrap over the R runs, B = 2000 resamples, resampling (success, time) pairs
  with replacement, RNG splitmix64 seeded 20260928; TTS99 recomputed per resample with the same
  definition; CI = 2.5th and 97.5th percentiles (inf when the percentile lands on a p* = 0 resample).
- Times are measured with 16 runs sharing the CPU; they are per-run wall times under that load,
  not single-run-alone times. Stated in RESULTS.

## 6. Pass/fail rules (decisive)

- **R1, bit-exact reproduction.**
  (a) Legacy mode: `gset_bench data\gset\G<k>` (k = 1..5) prints output byte-identical to the
  pre-change binary; reference SHA-256 of that output, recorded now:
  G1 `9bfde93f963a673a343ae0362c9ff7e6f5e423db8d4a545697e21573ab7bb6d5`,
  G2 `1145b3aae205f5d45d29a5b853733daeee4da86afde7600a9745000b7bf1b9a0`,
  G3 `02f697a5e002d755ace915d733677884ea71cae74feb090ed7c55ecf6220860f`,
  G4 `0194c31b68fe7c936dccafcada2ba100c258e8147c06cff0d904245dae979ad9`,
  G5 `7af2a66fcbcb3ee92a2b1b017422f670ca9c728dc12b50a4376cb710fc5a1ef3`.
  (b) Integer engine, B1, seeds 1..8: for all 40 (instance, seed) pairs of G1-G5 the assignment
  equals `anneal_branch`'s; the best cuts are 11613, 11617, 11621, 11646, 11616; the best
  assignments hash to the SHA-256 values in RESULTS-gset.md.
  PASS iff (a) and (b) both hold.
- **R2, exact consistency.** In every run of every cell, cut == -E_tracked == -E_scratch.
  Plus: on 3 random instances, n = 16, integer weights uniform in [-1000, 1000], seeds 1, 2, 3,
  complete graph, the integer energy function equals a brute-force double-free int64 evaluation
  for all 2^16 states, and the engine's best of 8 runs at B10 is >= 0.99 of the exact optimum
  (reported, not decisive; only the energy agreement is decisive). PASS iff zero mismatches.
- **R3, coverage.** All 11 instances load with n, m and (for K2000) the weight counts of section 3,
  from files whose SHA-256 match section 3, and all 33 cells complete their R runs within the cap.
  PASS iff all 11 load and 33/33 cells complete.
- **R4, TTS reported.** Every completed cell reports p, t, TTS99 and its bootstrap CI, with CSV
  decimals as dots. PASS iff every completed cell has all four.
- **R5, green.** `check.bat` exits 0; the 53 existing PASS lines are all still PASS (count
  unchanged, no FAIL), and every new PASS line of the harness self-check passes.
- **R6, prediction: the targets are reachable on sparse +1 graphs.** p > 0 for G1 at B10 or B100,
  and p > 0 for G22 at B100. PASS iff both.
- **R7, prediction: K2000 is not solved by the unscaled schedule.** p = 0 for K2000 at all three
  budgets. PASS iff p = 0 in all three (i.e. the prediction holds). The best K2000 cut is reported
  either way.

Seven rules. Verdicts are reported as they come out; none is re-run with changed parameters.

## 7. What is not claimed

- No speed claim against any solver; the GPU is not used; no schedule tuning.
- Best-known values are literature targets, not optima; a cut above a target would be reported,
  and checked, but is not expected.
- Exploratory runs, if any, are labelled exploratory and do not change a verdict.
